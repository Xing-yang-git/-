# Phase 2 AI 内容审核 — 测试用例

## 一、发布流程

### 1.1 正常发布（C端）

| # | 用例 | 操作 | 预期结果 |
|---|------|------|---------|
| 1.1.1 | 发布闲置借出（正常内容） | 标题"宝宝推车"，描述"九成新只用了3个月"，上传1张实物照，提交 | 1. 发布成功，帖子进入「审核中」子tab 2. AI审核后自动上线，出现在「在线中」 |
| 1.1.2 | 发布闲置借出（无图片） | 标题"冲击钻"，描述"博世GBH2-20，带工具箱"，不传图 | 1. 发布成功，仅文本审核 2. AI审核后自动上线 |
| 1.1.3 | 发布闲置借出（4张图片） | 上传4张实物照 | 1. 上传成功，+"按钮消失 2. 4张图全部审核 |
| 1.1.4 | 发布闲置借出（超4张） | 尝试上传第5张 | 提示"最多 4 张"，无法继续添加 |
| 1.1.5 | 发布需求借入 | 标题"求借婴儿车"，描述"宝宝刚满月需要轻便折叠款" | 同 1.1.1 流程 |
| 1.1.6 | 发布技能求助 | 标题"帮忙代取快递"，描述"上班不方便取快递求邻居帮忙" | 同 1.1.1 流程 |

### 1.2 审核三级分流

| # | 用例 | 操作 | 预期结果 |
|---|------|------|---------|
| 1.2.1 | 🟢绿色-自动通过 | 发布正常闲置帖 | status=online，moderation_status=green，B端"发布审核"tab中可见（审核状态=审核通过） |
| 1.2.2 | 🟡黄色-待复核 | 发布含微信号/二维码的帖子 | status=pending_review，moderation_status=yellow，C端「审核中」可见，B端"发布审核"tab可见（黄底） |
| 1.2.3 | 🔴红色-自动拒绝 | 发布纯广告/违禁品内容 | status=offline，moderation_status=red，C端收到服务通知，B端"发布审核"tab可见（红底） |
| 1.2.4 | 图片模糊（边缘case） | 上传一张光线差、模糊的实物照 | 🟢绿色通过（标准放宽松） |
| 1.2.5 | 描述过于简短 | 标题"风扇"，描述留空 | 🟢绿色通过（标准放宽松） |
| 1.2.6 | 描述只有几个字 | 标题"篮球"，描述"九成新" | 🟢绿色通过 |

### 1.3 AI 审核失败降级

| # | 用例 | 操作 | 预期结果 |
|---|------|------|---------|
| 1.3.1 | API Key 错误 | 故意配错 key | 重试1次失败 → 🟢自动通过，日志有报错 |
| 1.3.2 | API 超时 | 网络延迟导致超时 | 重试1次失败 → 🟢自动通过 |
| 1.3.3 | API 连续失败（熔断） | 短时间内多次发布 | 日志记录连续失败数，所有新帖通过 |
